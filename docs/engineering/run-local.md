# Run the BuddyDoc stack locally (development)

This document explains how to run the frontend (Expo web/mobile) and the backend services (orchestration + agents) locally for development and testing.

Prereqs

- Node.js (LTS), npm
- Python 3.10+ and venv
- Expo CLI (optional: `npm install -g expo-cli`)
- On Windows, PowerShell is used in these examples.

Overview

- Frontend: `frontend/` (Expo React Native)
- Orchestration: `backend/orchestration/` (FastAPI + Uvicorn)
- Agents: `backend/agent1/`, `backend/agent2/` (FastAPI mocks)

## Start orchestration

```powershell
cd 'C:\Users\HESHAN WITHARANA\OneDrive\Desktop\BuddyDoc\backend\orchestration'
. .\.venv\Scripts\Activate
# Optionally set the CORS origins via env var
$env:BUDDYDOC_CORS_ORIGINS = 'http://localhost:19006,http://127.0.0.1:19006'
uvicorn main:app --host 127.0.0.1 --port 8000
```

## Start frontend (web)

```powershell
cd 'C:\Users\HESHAN WITHARANA\OneDrive\Desktop\BuddyDoc\frontend'
# Start Expo web
npx expo start --web
```

- The frontend's runtime `ORCHESTRATION_URL` lives in `frontend/config.js`. For web testing the default `http://127.0.0.1:8000` works. For testing on a physical phone, change it to your PC's LAN IP (example `http://192.168.1.25:8000`) and ensure Windows Firewall allows incoming connections on port 8000 and Expo's ports.

```powershell
Invoke-WebRequest -Uri 'http://127.0.0.1:8101/api/v1/respond' -Method POST -Body (ConvertTo-Json @{ text = 'hello' }) -ContentType 'application/json' -UseBasicParsing | Select-Object -ExpandProperty Content

# Orchestrator

Invoke-WebRequest -Uri 'http://127.0.0.1:8000/api/v1/orchestrate' -Method POST -Body $body -ContentType 'application/json' -UseBasicParsing | Select-Object -ExpandProperty Content
```

Troubleshooting

- CORS errors (browser): ensure orchestration and agents have CORS configured to allow `http://localhost:19006` (or the origin shown in your browser). Set `BUDDYDOC_CORS_ORIGINS` as shown above and restart the server.
- Expo mobile can't download bundle: ensure PC and phone are on same network and firewall is open.
- Ports in use: use `netstat -aon | findstr ":<port>"` and kill the process if necessary.
